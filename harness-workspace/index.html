外部事件：告警与用户需求

外部事件主要由各业务系统通过 Webhook 推送。Webhook 接口先验签、去重并将事件写入持久 Inbox，成功落盘后再确认接收；后台 Worker 异步读取 Inbox，将事件关联到已有 Task 或创建新 Task，按需调用 Harness Agent / SuperAgent。Scheduler 是内部触发器，到期直接向同一个 Inbox 写事件，无需绕路调用 HTTP Webhook。

场景系统行为
线上服务报警监控系统通过 Webhook 推送告警，Inbox 去重并关联原 Task；Worker 调用 Magpie、监控和知识能力生成调查结果。
用户提出需求需求系统通过 Webhook 发送事件，Inbox 落盘；Worker 创建或关联 Task，在 Kanban 管理诉求、责任和产物。
定期巡检Scheduler 在同一后端直接写入 Inbox；Worker 唤醒任务，更新进展，并安排下次检查。

设计来源：[A1] Anthropic《Building always-on agents》（2026-11-13）。它提出 Inbox、Timers、Memory、Permissions、Outbox 五个长期运行原语；本项目首期只落地当前需要的持久 Inbox、定时触发和任务状态，不为每个原语拆分独立服务。

已经确定的设计决策

议题决策
MultiCA目标架构彻底废弃，不继承 Go Backend、Issue/Squad/Daemon、原 API 和数据模型；现有代码仅作经验参考。
技术栈TypeScript-first，React + Node.js 单体后端和 Worker；数据优先使用现有 MySQL，Go/Python 只在已有能力适合时复用。
第一优先级 P0Magpie Chat 真实贯通：Web Chat → 选定 Runtime → 原生加载 Magpie → 真实模型工程任务。当前不以 SuperAgent、Kanban 或 Webhook 为建设前置。
Harness领域 Harness（Magpie）以现有仓库和原生机制复用，不为其开发第二套 Builder / Service Registry；不能只把 SKILL.md 内容拼进 Prompt。
SuperAgent底层持续工作机制，由显式 @superagent、Scheduler、告警或需求事件唤醒；保存目标、执行反馈和下一步。
持续改进从真实任务的失败和使用反馈自然改进 Harness / Tools；不先建独立通用 Evaluation 平台。
后置能力独立 Bot UI、BYOC、复杂多租户、CMS 后置；外部告警与用户需求的事件接收是核心能力。

实施优先级：先 Magpie Chat，再扩展其他能力

P0 的完成线：打开 Web Chat，选择 Codex、Pi 或 Claude Code，在真实 Magpie 仓库 / Workspace 环境中调用领域 Skills 与工具，完成一个有证据的模型工程任务；能看到流式执行、工具过程及结果，继续对话不丢上下文。全过程不依赖 MultiCA。
P0

Magpie Chat 原生集成

实现自有 Web Chat → Runtime 调用与流式事件；以 Magpie 现有仓库为领域 Harness 来源，复用原始 Skills / Rules / Context / Tools，不重写 Agent Loop 或复制一套 Skill 管理系统。用真实 DaVinci 任务验证；先打通完成任务所必需的一条知识或监控工具链。

P1

补充内部 Knowledge / Integrations

在 P0 实际暴露的缺口上扩展内部文档、Repo Identity、监控、训练和业务 API；按真实场景接入，不先开发通用 RAG / MCP 市场。

P2

SuperAgent 持续工作

仅显式 @superagent 才从 Chat 进入该通路；以已验证的 Magpie Chat 能力为基础，持久化 Task、执行反馈与下一步，验证跨 Session 恢复。

P3

Scheduler / Kanban / Webhook Inbox

Scheduler 创建定时事件，外部告警和需求通过 Webhook 先进持久 Inbox；关联 Task 后由 Worker 唤醒服务，Kanban 展示同一任务的状态与人工决策。

P4

生产化与扩展

补齐认证、授权和用户隔离；再按需求接企业微信 Bot、自带容器 BYOC。所有新模块均不引入 MultiCA 的兼容责任。

还需要实际解决的问题

真实 CLI 契约

Codex / Pi / Claude Code 在目标开发机上的会话保持、流式事件、工具审批与恢复语义是什么？

领域 Harness 复用

Magpie 的真实仓库结构与各 Runtime 的 Skill 装载方式如何对应？不能只把 SKILL.md 拼进 Prompt。

首个内部知识与工具

优先打通 DaVinci 的知识文档与监控查询；明确接口、权限和结果引用，不预建通用知识平台。

生产执行边界

多用户登录、凭证隔离、运行权限、可重复执行的非幂等操作如何处理？不把当前单机原型暴露公网。

发布状态说明

此页面是已经公开发布的方案与路线图，不是可调用模型的在线 Chat 服务。现有 Node 原型可本地运行，但真实 CLI、用户认证和隔离尚未完成，不能直接对公网开放。在线运行服务需要具有受控身份与持续进程能力的部署环境。
