重新构建 AI-Native Harness

构建企业内部使用的定制 Harness：Web Chat、定时任务、Kanban 和外部告警/需求事件复用一套执行基础；SuperAgent 是底层持续工作机制。

Web-first显式 @superagentMagpie = 模型工程 Harness零 MultiCA 运行依赖外部事件响应

目标与范围

Chat、定时任务和 Kanban 是内部工作入口；外部告警与用户需求主要经 Webhook 写入 Inbox，Bot 是可选的外部交互渠道。Chat 可通过自建 Harness Agent 或已有 Runtime 工作，SuperAgent 负责持续任务、组合调用和恢复。

01 · Use

交互式 Harness Agent

Chat 通过自建 Harness、领域 Skills 和内网工具工作，也可使用 Codex / Pi / Claude Code；不隐式升级 SuperAgent。

02 · Equip

接入领域工作能力

Magpie 是模型工程领域 Harness，按需加载现有 Skills、规则、上下文、知识和工具。

03 · Continue

事件驱动的持续执行

Chat 只有显式 @superagent 才走 SuperAgent 通路；Scheduler 或外部告警/需求可按配置唤醒它。

外部事件：告警与用户需求

外部事件主要由各业务系统通过 Webhook 推送。Webhook 接口先验签、去重并将事件写入持久 Inbox，成功落盘后再确认接收；后台 Worker 异步读取 Inbox，将事件关联到已有 Task 或创建新 Task，按需调用 Harness Agent / SuperAgent。Scheduler 是内部触发器，到期直接向同一个 Inbox 写事件，无需绕路调用 HTTP Webhook。

场景系统行为
线上服务报警监控系统通过 Webhook 推送告警，Inbox 去重并关联原 Task；Worker 调用 Magpie、监控和知识能力生成调查结果。
用户提出需求需求系统通过 Webhook 发送事件，Inbox 落盘；Worker 创建或关联 Task，在 Kanban 管理诉求、责任和产物。
定期巡检Scheduler 在同一后端直接写入 Inbox；Worker 唤醒任务，更新进展，并安排下次检查。

依据 Anthropic《Building always-on agents》(2026-11-13)：Inbox、Timer、Memory、Permissions、Outbox 是构建持续响应的外围原语。首期采用数据库与同一个后台 Worker；不为这些原语单独拆微服务。

已经确定的设计决策

议题决策
MultiCA目标架构彻底废弃，不继承 Go Backend、Issue/Squad/Daemon、原 API 和数据模型；现有代码仅作经验参考。
技术栈TypeScript-first，React + Node.js 单体后端和 Worker；数据优先使用现有 MySQL，Go/Python 只在已有能力适合时复用。
Harness领域 Harness（Magpie）以现有仓库和原生机制复用，不为其开发第二套 Builder / Service Registry。
SuperAgent底层持续工作机制，由显式 @superagent、Scheduler、告警或需求事件唤醒；保存目标、执行反馈和下一步。
持续改进从真实任务的失败和使用反馈自然改进 Harness / Tools；不先建独立通用 Evaluation 平台。
后置能力独立 Bot UI、BYOC、复杂多租户、CMS 后置；外部告警与用户需求的事件接收是核心能力。

推进路线

01

建立独立系统骨架

自有 Web / Backend；Chat 能使用自建 Harness Agent 与成熟 Runtime；@superagent 显式路由，禁止旧系统兼容路径。

02

真实 Magpie 与内部能力贯通

按原生约定加载模型工程 Harness；接入一个内部知识来源、一个真实业务工具，完成模型服务问题分析。

03

SuperAgent 持续任务与外部事件

告警或需求先进入持久 Inbox，再进入 Task；SuperAgent 保存 Taskbook、执行结果和下一步，重启后能够继续。

04

Scheduler / Kanban

定时任务产生 Inbox Event；Kanban 统一管理需求、告警、执行进展和人工决策，不维护第二套任务事实。

05

生产化与扩展

认证、隔离、授权审批；接入企业微信等 Bot；按实际需求再考虑自带容器 BYOC。

还需要实际解决的问题

真实 CLI 契约

Codex / Pi / Claude Code 在目标开发机上的会话保持、流式事件、工具审批与恢复语义是什么？

领域 Harness 复用

Magpie 的真实仓库结构与各 Runtime 的 Skill 装载方式如何对应？不能只把 SKILL.md 拼进 Prompt。

首个内部知识与工具

优先打通 DaVinci 的知识文档与监控查询；明确接口、权限和结果引用，不预建通用知识平台。

生产执行边界

多用户登录、凭证隔离、运行权限、可重复执行的非幂等操作如何处理？不把当前单机原型暴露公网。

发布状态说明

此页面是已经公开发布的方案与路线图，不是可调用模型的在线 Chat 服务。现有 Node 原型可本地运行，但真实 CLI、用户认证和隔离尚未完成，不能直接对公网开放。在线运行服务需要具有受控身份与持续进程能力的部署环境。
