从 MultiCA 退出，
重新构建 AI-Native Harness

不是再做一个多 Agent 管理平台，而是让 Codex、Pi、Claude Code 真正利用领域 Harness、内部知识和业务工具，完成单次或持续性工作。

Web-first显式 @superagentMagpie = 模型工程 Harness零 MultiCA 运行依赖

目标与范围

Chat、Scheduler 和 Board 是 Web 内部入口；企业微信等 Bot 是外部交互入口。Agent Runtime 和 SuperAgent 是后端可调用能力。Harness 提供领域工作方法、知识与工具，不新造 Agent Loop。

01 · Use

直接使用成熟 Agent

普通 Chat 直接调用选择的 Codex / Pi / Claude Code；不进行隐式 SuperAgent 升级。

02 · Equip

接入领域工作能力

Magpie 是模型工程领域 Harness，按需加载现有 Skills、规则、上下文、知识和工具。

03 · Continue

按需持续执行

只有显式 @superagent 才进入 SuperAgent 通路，组合 Runtime 并维持持久 Task。

已经确定的设计决策

议题决策
MultiCA目标架构彻底废弃，不继承 Go Backend、Issue/Squad/Daemon、原 API 和数据模型；现有代码仅作经验参考。
技术栈TypeScript-first；首版单体后端 + Worker。Go/Python 仅在复用现成能力或需要时采用，不引入微服务平台。
Harness领域 Harness（Magpie）以现有仓库和原生机制复用，不为其开发第二套 Builder / Service Registry。
SuperAgent一种后端服务能力，组合现有 Runtime；保存目标、结果、下一步，不重写 Agent 内部 Loop。
持续改进从真实任务的失败和使用反馈自然改进 Harness / Tools；不先建独立通用 Evaluation 平台。
后置能力Bot、BYOC、复杂多租户执行隔离、完整 CMS，在核心工作闭环跑通后推进。

推进路线

01

建立独立系统骨架

自有 Web / Backend；普通 Chat 直连 Runtime，显式 @superagent，统一执行事件。禁止旧系统兼容路径进入新代码。

02

真实 Magpie 与内部能力贯通

按原生约定加载模型工程 Harness；接入一个内部知识来源、一个真实业务工具，完成模型服务问题分析。

03

SuperAgent 持续任务闭环

Taskbook 持久化，执行结果先吸收再推进；关闭 Chat 或重启后不依赖父 Session 的隐含上下文继续工作。

04

Scheduler / Board

定时触发、查看运行记录、继续、停止和人工决策，所有入口共享 Task / Run，不产生第二套任务事实。

05

生产化与扩展

认证、隔离、授权审批；接入企业微信等 Bot；按实际需求再考虑自带容器 BYOC。

还需要实际解决的问题

真实 CLI 契约

Codex / Pi / Claude Code 在目标开发机上的会话保持、流式事件、工具审批与恢复语义是什么？

领域 Harness 复用

Magpie 的真实仓库结构与各 Runtime 的 Skill 装载方式如何对应？不能只把 SKILL.md 拼进 Prompt。

首个内部知识与工具

优先打通 DaVinci 的知识文档与监控查询；明确接口、权限和结果引用，不预建通用知识平台。

生产执行边界

多用户登录、凭证隔离、运行权限、可重复执行的非幂等操作如何处理？不把当前单机原型暴露公网。

发布状态说明

此页面是已经公开发布的方案与路线图，不是可调用模型的在线 Chat 服务。现有 Node 原型可本地运行，但真实 CLI、用户认证和隔离尚未完成，不能直接对公网开放。在线运行服务需要具有受控身份与持续进程能力的部署环境。
