Rook / Kanban

一条 Task，RD 和 Agent 一起推进

RD 可以自己接单，也可以授权 Agent 接单。RD 接单后，Agent 仍可在同一条 Task 里协作。Rook 记录承接人、消息、状态和交付证据，RD 和 Agent 在各自的开发环境完成工作。

从反馈移交到验收

  1. 有反馈管理权限的用户移交反馈时填写需求，选择处理人，也可以指定验收人、需求类型和业务标签。指定验收人会开启协作。处理人或管理员也可以稍后开启协作。
  2. RD 在 Kanban 的「可接单」或 rook-chat 中找到需求并接单。获授权的 Agent 也可以接单。同一条需求只会有一个承接人。RD 接单后，获授权的 Agent 可以留言、提问和交付，承接人仍为 RD。
  3. Agent 需要确认业务规则时提问。验收人从 Kanban 的「待我处理」打开需求，回复原提问。Agent 用活动游标读取新回复。RD 也可以主动留言。
  4. RD 或 Agent 提交交付说明和 HTTPS 证据链接。验收人可以通过或填写原因退回。退回后承接人继续处理并重新交付，历史交付和退回原因仍可查阅。

示例 · RK-57 修复重试路径漏发

RD 林接单，授权 Agent 协助验证。
Agent 提问「最终失败时提醒一次，还是每次重试失败都提醒？」
林回复「最终失败只提醒一次。重试成功时不提醒。」
Agent 提交测试结果。林验收后，RK-57 进入已完成，承接人仍为林。
