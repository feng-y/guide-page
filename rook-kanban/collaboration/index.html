Rook / Kanban

一条 Task，RD 和 Agent 一起推进

Rook 保存承接人、状态、双方消息和交付证据。RD 和 Agent 在原有开发环境工作。开发 Agent 用 rook-chat 读取同一条 Task，回写消息和交付。

交互状态与权限rook-chat 契约落地与验收

从卡片接单到验收

  1. 一条反馈移交为 Task。卡片展示问题、复现信息和验收条件。RD 可从授权范围内的「可接单」列表接单。自动派发时，外部派发流程把 Task ID 传给已授权的开发 Agent。
  2. 开发 Agent 用 rook-chat 读取 Task。RD 或 Agent 接单成功后，Task 进入「处理中」。RD 已接单时，其授权的开发 Agent 可以协作，承接人仍为 RD。
  3. Agent 在开发中遇到未定的业务规则，向指定 RD 发问。Kanban 卡片显示「待 RD 回复」。RD 在 Task 详情回复，也可以主动发消息。开发 Agent 再次读取时，只读取游标之后的消息。
  4. RD 或 Agent 提交 MR 链接、验证结果和仍待确认的事项。卡片显示「待验收」。验收人通过后，Task 进入「已完成」。退回理由写进同一条 Task，承接人据此继续开发。

  • 移交时明确哪些 RD 可以接单。首期可使用 Task 上的小范围授权名单。进入名单只授予该 Task 的访问权限。接单后由当前承接人负责开发，协作 RD 负责回复，验收人负责通过或退回。试点默认协作 RD 和验收人为同一人，可在移交时指定。
  • Task 消息按 Task 权限访问。来源 Chat、快照和 MR 分别沿用它们自身的权限。用户可以从来源摘录必要信息到 Task，经确认后供协作者阅读。
  • 本地 Agent 可在 RD 已授权的身份下协作。无人值守开发 Agent 使用与 Task 绑定的独立授权。Rook 从服务端身份确认作者和操作权限。收到 Agent 接单时，Rook 再核对 Task 和授权是否匹配。
  • 现有反馈移交和已完成 Task 继续可读。启用协作的 Task 通过专门的接单、交付和验收动作变更状态，旧移列入口也执行同样的校验。

rook-chat 契约

以下名称用于评审。Web 和 rook-chat 调用 Rook Backend 的同一套业务操作。

操作输入与结果
读取 Task输入 Task ID。返回标题、目标、复现信息、验收条件、承接人、状态和 revision。可按当前身份列出可接单 Task。
接单输入 Task ID、revision、requestId。Rook 在一个事务内校验权限、确认唯一承接人、推进状态。
读取和追加消息读取可带 cursor，返回增量消息及下一游标。写入带 requestId。需要 RD 回复时，指定已获授权的 RD。回复通过 replyTo 关联原提问。
提交交付输入 Task ID、当前 revision、MR、验证摘要和 requestId。Rook 保存一版交付并标记「待验收」。
验收验收人在 Web 针对当前交付版本通过或退回。退回时填写原因。

同一个 requestId 重试同一写入返回原结果。接单冲突时先重读 Task，未接单的一方停止开工，后续读取仍按 Task 权限校验。RD 回复时保存消息。外部 Agent 何时恢复执行由它的开发流程决定。

落地与验收

  1. 打通授权读取和 RD 主动接单。 扩展现有 Kanban 权限和接单规则。让真实 RD 用 rook-chat 读取一条反馈 Task。用两份开发环境同时接单验证只有一方成功。
  2. 打通 Task 消息与真实交付。 Agent 发问，RD 从 Kanban 回复，Agent 按游标读到回复并提交 MR。RD 退回一次再通过。重复发送、断开后按游标补读和其他用户越权分别验证。
  3. 接入现有自动派发。 先确认可用的外部派发入口，再用它传 Task ID 给已授权 Agent。验证 RD 主动接单和自动接单同时到达、派发重试、授权撤销时的结果。

Kanban 用「可接单」找新需求，用「待我处理」找待回复和待验收。跨入口的人工决策出现后再评估独立 Inbox。
