Rook / Kanban上一轮 A、B、C 方案

Agent 怎么接手一条需求

A 已支持反馈移交和需求流转。这里用同一条模拟需求对比三版 B。切换方案后，点按钮走一遍 Agent 开工、交付和人工验收。

实施顺序

方案谁推动下一步新增依赖何时值得做
B1 从卡片发起处理人启动。Agent 交付。处理人验收。Task 关联已授权的 Chat。Rook Backend 保存交付和验收结果。现在。用一条真实反馈验证验收闭环。
B2 有容量再开工处理人确认需求可开工。有容量时，Agent 领取已确认的需求。可开工队列、WIP 上限、原子领取。示例按验收人计入 WIP。已开始的需求反复积压在验收阶段。
B3 等事件继续处理人启动。已登记的 CI 事件让 Agent 继续同一条需求。已授权的 CI 事件来源、去重、按 Task 关联、恢复前校验权限。处理人频繁手动催 Agent 跟进 CI 或评论。

建议先做 B1

保留现有三列。Agent 提交后，卡片在「处理中」显示「待验收」。处理人可以用「待我验收」直接打开交付证据。退回时保留理由和前一版证据。处理人通过后，需求进入「已完成」。

独立 Inbox 等到 Kanban 之外也出现由同一批人处理的审批再评估。B3 的 CI 事件属于执行触发，后续可以接入 Durable Inbox。
