人把什么交给 Agent？

同一个场景：自动化任务失败后，用户偶尔收不到提醒。三版分别让用户交给 Agent 一条需求、一次协作，或一个持续目标。切换方案，看看工作从哪里开始，最后停在哪里。

哪一种适合 Rook

方案用户先去哪什么持续存在用户最后验收什么新增依赖
B1 委派需求Kanban 需求详情Task。处理人与 Agent 在同一张卡片上澄清、执行和验收。一份交付。通过后 Task 完成。Task 关联已授权 Chat，保存交付和验收。
B2 Chat 协作ChatChat。人与 Agent 边查边定范围，可以产生多个独立 Task。已经解决的事项留在 Chat。用户只把仍需他人跟进的事项加入 Kanban。从 Chat 摘要确认后创建 Task，并保存授权来源链接。
B3 托管目标SuperAgent 目标目标。Agent 在用户授权的范围内根据新观测创建、跟进 Task。目标是否持续达标。某个 Task 完成后，目标继续生效。目标、事件来源、指标观测、运行预算和人工审批。

现阶段推荐 B1

Rook 已经接收反馈并创建 Task。B1 让 Agent 和处理人围绕原 Task 澄清要求、补充证据和验收。用户可以在卡片上接着交互。

如果用户通常先在 Chat 里弄清问题，再把少数事项交给团队，首选 B2。如果用户想让 Agent 承担一段时间内的持续责任，再选 B3。

独立 Inbox 在三版里的价值不同。B1 用 Kanban 的「待我验收」。B2 的决策留在当前 Chat。B3 若同时管理多个目标，跨目标的人工审批才有理由集中到独立 Inbox。
