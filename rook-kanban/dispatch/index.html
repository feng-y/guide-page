Rook / KanbanAgent 交付流程

RD 和 Agent 怎么协作

Rook 记录 Task 状态，供 RD 和 Agent 协作。开发在现有环境完成。承接人是 Task 的属性，RD 主动接单与自动派给 Agent 共用同一条 Task。三套方案对比的是 RD 怎样把一个决定交回给 Agent。

同一个问题，三种协作结果

方案RD 怎么操作Rook 保存什么开发 Agent 下一次拿到什么适用场景
一 · Task 对话打开关联 Chat，回复一条消息，可以继续追问。Task 与 Chat 的关联、双方消息、待 RD 回复。按游标读取新消息，结合对话理解要求。问题需要来回澄清。
二 · 待决问题在 Kanban 的「待我处理」打开问题，选一个决定或要求补充信息。问题、指定决策人和决策结果。按问题 ID 读取明确结果，根据结果继续工作。Agent 大部分时间独立开发，少数分歧需要 RD 拍板。
三 · 验收条件检查 Agent 提议的条款改动，确认后生效。当前生效的验收条件、版本和确认人。读取新版本的验收条件，后续交付标明依据的版本。需求经常改范围，开发和验收需要对齐同一版条件。

建议先做一 · Task 对话

首期把已授权 Chat 关联到 Task，并在卡片上显示「待 RD 回复」。开发 Agent 可以提问，RD 可以回复或主动补充要求。多轮确认都能留在同一个地方。

如果试用显示多数交互只是一次拍板，改用二。若反复出现开发和验收依据不同版本的情况，再引入三。看板内先显示需要 RD 处理的 Task。

共同边界

  • RD 主动接单或开发流程自动派给 Agent 时，Rook 确认承接人并记录状态。并发接单只允许一方成功。
  • 开发 Agent 通过 rook-chat 读取授权 Task。首期需扩展 Task 读取以及选定方案所需的协作接口。开发工具在现有环境内执行。
  • 示例从「处理中」开始。Agent 等 RD 时，Task 继续显示「处理中」，同时标出「待 RD 处理」。RD 回复、决定或确认后，开发 Agent 获取协作结果。交付仍回写到原 Task，由人验收。
