Rook / Kanban交付流程

RD 和 Agent 怎么一起开发

三套都支持 RD 主动接需求，也支持 Rook 自动派给 Agent。选择任一方案和入口，用同一条「修复重试路径漏发」看 RD 接下来在哪里操作、该做什么。

三个方案的 RD 交互

方案RD 主动接需求自动派给 AgentRD 的主要操作首期新增依赖
一 · Task 对话RD 从 Task 开启关联 Chat，自己开发或请 Agent 帮忙。Agent 拉取后开始开发。遇到歧义，在关联 Chat 点名 RD。在同一个 Chat 回复问题、补约束、追问证据。Task 关联已授权 Chat，展示待 RD 回复和待验收。
二 · 交付审阅RD 自己开发，也可以把一份交付委派给 Agent。Agent 独立开发，提交 PR/MR 和证据后请 RD 审阅。在交付物上写具体意见，通过或退回。Agent 回同一交付物更新。记录交付物版本、验证结果与审阅结果。
三 · 交接控制权RD 自己开工，遇到问题可保存进度，把整条 Task 交给 Agent 继续。Agent 先执行。RD 需要亲手修改时接管已有分支和进度。交出、接管、交回。任何时刻只有一个执行者推进交接中的分支。保存交接点和未完成事项，记录当前执行者，校验交接版本并防止并发写入。

推荐先做方案一

Rook 已有 Chat 和 Kanban。先验证同一条 Task 从两个入口开工后，RD 能否在一个地方看到 Agent 的问题并继续工作。方案二适合 RD 通常只做异步审阅的团队。方案三适合 RD 经常需要亲手接续 Agent 的代码改动。

共同规则

  • RD 可从有权限的待处理需求中主动接单。用户确认允许自动派发的 Task 后，Rook 也可以按 Project 规则派给已授权的 Agent。两条入口由 Rook 原子确认接单。同一条 Task 只接受一次有效接单。
  • 开发 Agent 用 rook-chat 按 ID 读取 Task 的目标、范围、复现信息和验收条件。Rook 校验读取身份。读取本身不改变任务状态。
  • 接单确认后 Task 进入「处理中」。此后方案一让 RD 接续对话，方案二让 RD 审阅交付物，方案三让 RD 转移开发控制权。通过验收后 Task 才进入「已完成」。
  • 先用 Kanban 里的「待我处理」呈现需要 RD 回复、审阅或接管的 Task。跨入口的人工决策出现后，再评估独立 Inbox。
