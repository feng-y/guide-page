Proto Shared Access SDK

统一访问 singular message 与 repeated message，对调用方隐藏字段形态差异，同时明确 ownership / Arena 生命周期。

目标不是 shared_ptr 化 protobuf，而是提供“统一读取 + 可选迁移/接管”的访问层。

1. 目标模型

Proto Message ├── singular child │ └── Message └── repeated children ├── Message ├── Message └── Message SDK 对上统一暴露： ProtoView<T> // 只读访问 ProtoMutableView<T> // 可写访问 ProtoMover<T> // ownership 迁移
统一访问

调用方不关心底层字段是 singular 还是 repeated，只面向 span-like view。

零额外序列化

直接访问 protobuf 内存对象，不做 Serialize / Parse。

Arena-aware

迁移能力区分 heap 与 same-arena，避免错误跨生命周期挂接。

语义分层

Read/View 与 Move/Ownership 分开，避免“共享访问”误解成共享所有权。

2. 推荐 API

namespace proto_access {

template <class T>
class ProtoView {
 public:
  size_t size() const;
  const T& operator[](size_t i) const;

  const T* data_at(size_t i) const;
  bool empty() const;
};

template <class T>
class ProtoMutableView {
 public:
  size_t size() const;
  T& operator[](size_t i);
  T* mutable_at(size_t i);
};

template <class T>
struct MoveOptions {
  bool same_arena = false;
  bool preserve_order = true;
};

template <class T>
class ProtoMover {
 public:
  // singular -> singular
  static void MoveSingular(T* src_parent, T* dst_parent);

  // repeated[index] -> repeated
  template <class SrcRepeated, class DstRepeated>
  static void MoveRepeatedElement(
      SrcRepeated* src,
      size_t index,
      DstRepeated* dst,
      MoveOptions<typename SrcRepeated::value_type> options = {});

  // repeated 全量迁移
  template <class Repeated>
  static void SwapRepeated(Repeated* src, Repeated* dst);
};

}  // namespace proto_access

3. Singular 与 Repeated 的统一 View

template <class T>
class SingularView {
 public:
  explicit SingularView(const T* ptr) : ptr_(ptr) {}

  size_t size() const { return ptr_ ? 1 : 0; }
  bool empty() const { return ptr_ == nullptr; }

  const T& operator[](size_t i) const {
    assert(i == 0 && ptr_);
    return *ptr_;
  }

 private:
  const T* ptr_;
};

template <class T>
class RepeatedView {
 public:
  explicit RepeatedView(
      const google::protobuf::RepeatedPtrField<T>* field)
      : field_(field) {}

  size_t size() const { return field_->size(); }
  bool empty() const { return field_->empty(); }

  const T& operator[](size_t i) const {
    return field_->Get(static_cast<int>(i));
  }

 private:
  const google::protobuf::RepeatedPtrField<T>* field_;
};

上层可以进一步用 type-erasure / variant 封成统一的 ProtoView<T>，让遍历逻辑完全一致：

for (size_t i = 0; i < view.size(); ++i) {
  Consume(view[i]);
}

4. 迁移语义

场景推荐原语复杂度备注
singular → singularrelease_xxx() + set_allocated_xxx()O(1)heap ownership transfer
same Arena singular → singularunsafe_arena_release_xxx() + unsafe_arena_set_allocated_xxx()O(1)要求 same arena / 生命周期一致
repeated last → repeatedReleaseLast() + AddAllocated()O(1)不保留 source 尾元素
repeated[i] → repeatedSwapElements() + ReleaseLast()O(1) 或 O(n)是否保序决定复杂度
整个 repeated A ↔ BSwap()近似 O(1)B 为空时等价于整体迁移

5. 关键实现

5.1 Singular ownership transfer

// generated protobuf API example
auto* child = parent->release_a();
parent->set_allocated_b(child);

5.2 Same Arena singular transfer

auto* child = parent->unsafe_arena_release_a();
parent->unsafe_arena_set_allocated_b(child);

5.3 Repeated 单元素迁移

template <class T>
void MoveRepeatedElement(
    google::protobuf::RepeatedPtrField<T>* src,
    int index,
    google::protobuf::RepeatedPtrField<T>* dst,
    bool preserve_order) {

  const int last = src->size() - 1;

  if (index != last) {
    if (!preserve_order) {
      src->SwapElements(index, last);
    } else {
      for (int i = index; i < last; ++i) {
        src->SwapElements(i, i + 1);
      }
    }
  }

  T* ptr = src->ReleaseLast();
  dst->AddAllocated(ptr);
}

5.4 Same Arena repeated

T* ptr = src->UnsafeArenaReleaseLast();
dst->UnsafeArenaAddAllocated(ptr);

6. SDK 建议接口形态

// 只读统一访问
auto view = proto_access::MakeView(parent.a());
auto view = proto_access::MakeView(parent.children());

// 可写统一访问
auto view = proto_access::MakeMutableView(parent.mutable_a());
auto view = proto_access::MakeMutableView(parent.mutable_children());

// ownership migration
proto_access::MoveField(parent, "a", "b");

proto_access::MoveElement(
    parent.mutable_a_list(),
    index,
    parent.mutable_b_list(),
    {.same_arena = true, .preserve_order = false});

建议：如果 SDK 追求性能与类型安全，不要真正用字符串反射作为主路径。主接口优先模板 / generated accessor；reflection 可作为动态 fallback。

7. Reflection 版统一访问

struct DynamicMessageView {
  const google::protobuf::Message* parent;
  const google::protobuf::FieldDescriptor* field;

  int size() const {
    const auto* r = parent->GetReflection();
    return field->is_repeated()
        ? r->FieldSize(*parent, field)
        : (r->HasField(*parent, field) ? 1 : 0);
  }

  const google::protobuf::Message& get(int i) const {
    const auto* r = parent->GetReflection();
    return field->is_repeated()
        ? r->GetRepeatedMessage(*parent, field, i)
        : r->GetMessage(*parent, field);
  }
};

Reflection 很适合“路径 SDK / schema 动态访问”，但如果是模型推理热路径，建议把 descriptor/path 解析结果缓存起来。

8. 推荐架构

Access Layer
统一 singular / repeated 读取与遍历。
Path Layer
解析 a.b.c，缓存 FieldDescriptor 链。
Ownership Layer
负责 release / add / set_allocated / arena 校验。
Policy Layer
是否保序、是否允许 unsafe arena、目标字段非空时如何处理。

9. 必须明确的边界

✓ “共享访问”可以做到统一 view，不复制 message。

✓ ownership migration 可以做到子树级迁移，不需要 serialize / parse。

! Protobuf 原生不是 shared_ptr 语义，而是 parent ownership + Arena lifetime。

! unsafe_arena_* 只有在 Arena 关系明确时才应该由 SDK 开放。

! repeated 中间元素删除如果必须保持顺序，本质上仍有 O(n) 容器移动成本，但不会深拷贝复杂子 message。

10. 最终建议

如果这是线上模型/特征链路 SDK，推荐将核心能力定义为：

ProtoPath
   ↓
ResolvedField
   ↓
MessageView        // singular/repeated 统一读
MutableMessageView // singular/repeated 统一写
OwnershipMover     // 显式 ownership transfer
ArenaPolicy        // 生命周期与 unsafe 约束

不要把“访问”和“迁移”做成一个接口。前者是引用语义，后者是 ownership mutation；拆开之后 API 会稳定很多，也更适合后续接入 protobuf reflection、动态 path 和模型输入 binding。
